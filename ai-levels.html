정밀한 평가가 아니라 실행 순서를 정하기 위한 간단한 성숙도 분류입니다.

1단계 기본 역량을 먼저 정비하세요

요청 구조와 프로젝트 세팅이 잡히면 이후 Codex 작업 지시의 품질도 안정됩니다.

기본 역량 모듈로 이동
권장 과제

진단 결과에 맞춰 실행 모듈을 선택하세요

모든 내용을 한 번에 소화할 필요는 없습니다. 현재 단계의 실행 과제를 완료한 뒤 다음 단계로 이동하면 됩니다.

1단계

기본 역량

AI에게 일을 설명하는 방식을 먼저 표준화합니다.

프롬프트 비교요청 품질의 기준을 정합니다. 프로젝트 만들기반복해서 쓰는 업무 맥락을 저장합니다. 멀티 페르소나의사결정에 필요한 관점을 나눕니다.
2단계

플러그인

익숙한 업무 파일에 AI를 적용합니다.

Excel에서 ChatGPT 사용표 분석과 수식 점검을 자동화합니다. PowerPoint에서 ChatGPT 사용슬라이드 초안과 메시지 구조를 정리합니다.
3단계

Codex 실행

실제 파일을 읽고 고치는 작업을 Codex에 위임합니다.

Codex 앱 시작하기작업 지시와 결과 검수 흐름을 익힙니다. 실전 과제 8가지검수 가능한 단위의 결과물을 만듭니다.
4단계

GitHub와 배포

결과물을 저장하고 웹 주소로 공유합니다.

GitHub 저장과 공유파일과 변경 이력을 협업 자산으로 관리합니다. Vercel 배포배포 주소를 만들고 업데이트 흐름을 익힙니다.
5단계

자동화

반복 업무를 규칙과 워크플로우로 표준화합니다.

AGENTS.mdCodex가 지켜야 할 운영 규칙을 정의합니다. 나만의 Skill반복 작업 절차를 재사용 자산으로 만듭니다. 팀 설계작업 흐름을 역할과 책임으로 나눕니다. 하네스 엔지니어링AI가 안정적으로 일하는 환경을 설계합니다.
운영 기준

위임 범위가 커질수록 검수 체계도 함께 설계해야 합니다

Codex에게 더 많은 일을 맡길수록 사람의 역할은 실행에서 의사결정과 승인으로 이동합니다. 목표, 권한, 확인 기준이 더 중요해집니다.

위임 전

  • 목표, 제외 범위, 기대 결과를 함께 정의합니다.
  • 중요한 파일은 복사본이나 브랜치에서 다룹니다.
  • 확인 기준을 화면, 테스트, 문서 중 하나로 정합니다.

수행 중

  • 작업 단위를 검수 가능한 크기로 나눕니다.
  • Codex가 바꾼 파일과 변경 이유를 확인합니다.
  • 예상과 다르면 중단하고 조건을 다시 정의합니다.

운영 전환

  • AGENTS.md에 프로젝트 규칙과 금지 사항을 남깁니다.
  • 반복 요청은 Skill이나 템플릿으로 전환합니다.
  • 외부 시스템 연결은 권한과 승인 절차를 먼저 정합니다.

Codex 문서

Codex의 사용 환경, 설정, 앱, CLI, 웹, 통합 항목을 확인할 수 있습니다.
