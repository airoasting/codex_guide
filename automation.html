예약됨이란

정해진 주기로, 같은 작업을 알아서 반복하는 Codex입니다

예약됨(Automations)은 정해진 주기에 맞춰 Codex가 같은 작업을 알아서 반복 실행하는 기능입니다. "매일 아침 어제 올라온 이슈를 정리해 줘"처럼 주기와 할 일을 한 번 등록해 두면, 그 주기마다 Codex가 배경에서 그 일을 처리합니다. 손볼 것이 있을 때만 결과를 받은편지함(Triage)에 올리고, 아무 일도 없으면 조용히 보관 처리합니다.

⏰

정해진 주기

분 단위·매일·매주, 또는 직접 적은 cron 주기로 자동 실행합니다.

매일 09:00 · cron 직접 지정
🔁

배경 실행

내 프로젝트나 별도 워크트리에서 배경 작업으로 돌아갑니다.

작업 흐름을 끊지 않고 실행
📥

결과만 모임

보고할 게 있을 때만 받은편지함(Triage)에 쌓이고 없으면 보관됩니다.

소음 없이 핵심만 통보

한 번 예약하면 매번 같은 지시를 다시 칠 필요 없이 일이 끝나 있습니다.
반복 점검과 정기 작업을 Codex에게 통째로 넘기는 단계입니다.

어디서 만드나

예약됨은 Codex 앱과 CLI에서 만듭니다. 평소처럼 스레드에서 "매일 ~ 해 줘"라고 말하면 Codex가 예약 작업으로 만들어 주고, 만든 작업은 왼쪽 사이드바의 예약됨 메뉴에 모입니다. 실행 결과는 받은편지함인 Triage에서 확인합니다.

시작하는 곳

새 채팅에서 시키고, 예약됨에서 관리합니다

Codex 앱이나 웹에서 새 채팅을 열고, "매일 아침 9시에 ~ 해 줘"처럼 시각과 할 일을 적으면 됩니다. Codex가 이를 반복 작업으로 알아채고 예약 작업으로 만들지 물어봅니다. 한 번 만든 예약은 왼쪽 사이드바의 예약됨 메뉴에서 모아 보고 관리합니다.

두 가지 유형

대화를 이어 갈지, 매번 새로 시작할지 고릅니다

예약됨에는 두 유형이 있습니다. 차이는 "예약이 켜질 때 같은 대화를 이어 갈지, 매번 새로 시작할지"입니다.

스레드형 · Thread

같은 대화로 되돌아온다
  • 지금 열어 둔 스레드에 붙는 반복 깨우기
  • 앞선 맥락을 그대로 이어 가며 실행
  • 오래 도는 명령 감시·연결한 서비스 점검·검토 루프에

독립형 · Standalone

매번 새 실행으로 시작한다
  • 주기마다 깨끗한 새 작업으로 시작
  • 결과는 각각 Triage에 따로 쌓임
  • 여러 프로젝트에 걸쳐 독립적으로 돌릴 때
고르는 기준

앞선 대화 맥락을 이어 가야 하면 스레드형, 매 실행이 서로 독립적이거나 한 작업을 여러 프로젝트에 걸쳐 돌려야 하면 독립형입니다. 정기 점검·정기 리포트 대부분은 독립형이 잘 맞습니다.

만드는 법

말로 설명하면, Codex가 예약 작업으로 만들어 줍니다

따로 설정 화면을 채울 필요 없이, 평소 스레드에서 "매일 아침 ~ 해 줘"처럼 주기와 할 일을 말하면 됩니다. Codex가 작업 프롬프트와 유형을 초안으로 잡아 줍니다. 그때 정하는 것은 다음 네 가지입니다.

1

주기

언제, 얼마나 자주 돌릴지입니다. 분 단위 간격·매일·매주, 또는 직접 적은 cron 식 가운데 고릅니다.

2

작업

켜졌을 때 할 일입니다. "어제 올라온 이슈를 분류해 줘"처럼 평소 Codex에게 시키듯 적습니다.

3

유형

스레드형과 독립형 중 고릅니다. 맥락을 이어 가면 스레드형, 매번 새로 시작하면 독립형입니다.

4

실행 위치

내 프로젝트에서 바로 돌릴지, 별도 워크트리에서 돌릴지입니다. 워크트리는 작업 중인 파일과 변경을 분리해 줍니다.

주기 고르기는 이렇게 나뉩니다.

짧은 간격으로 계속 깨워, 진행 중인 일을 따라붙어 점검할 때 씁니다.

관리하기

받은편지함에서 보고, 고치고, 멈춥니다

한 번 만든 예약은 예약됨 메뉴에서 확인하고 언제든 수정하거나 멈출 수 있습니다. 실행 결과는 받은편지함인 Triage에 쌓입니다. 배경에서 자동으로 돌기 때문에 처음 만들 때 권한을 알맞게 거는 것이 중요합니다.

이렇게 관리합니다

  • 예약됨 목록에서 등록한 작업·주기 확인
  • 주기·작업 내용·유형 수정
  • 잠시 끄기 또는 완전히 삭제
  • 결과는 Triage 받은편지함에서 점검

안전하게 거는 법

  • 샌드박스 권한을 작업에 맞게 좁게 설정
  • 읽기만 필요하면 read-only로
  • 되돌릴 수 없는 동작은 초안까지만
  • 처음엔 좁은 권한으로 시험한 뒤 넓히기
루프 엔지니어링(루프)과 무엇이 다릅니까?
루프는 지금 열어 둔 스레드 안에서 곧바로 돌리는 반복입니다. 예약됨은 주기에 맞춰 예약해 두는 것이라, 그 주기가 될 때마다 Codex가 배경에서 알아서 실행하고 결과만 받은편지함에 올립니다.
결과는 어디서 봅니까?
받은편지함인 Triage에서 봅니다. 보고할 게 있을 때만 Triage에 올라오고, 아무 일도 없으면 조용히 보관 처리돼 알림 소음이 적습니다.
파일을 바꾸거나 위험한 동작까지 자동으로 시켜도 됩니까?
예약 작업은 설정한 샌드박스 권한(읽기 전용, 작업공간 쓰기, 전체 접근) 안에서만 움직입니다. 되돌리기 어려운 동작은 권한을 좁게 두고 초안까지만 맡기는 것이 안전합니다.

자동화

예약됨까지 오면, 반복 점검과 정기 작업은 내 손을 떠나 정해진 주기에 알아서 돌아갑니다. 자동화 트랙을 모두 봤다면 인덱스로 돌아가 오늘 예약해 볼 작업 하나를 정하세요.
